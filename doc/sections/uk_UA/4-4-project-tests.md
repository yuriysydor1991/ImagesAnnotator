## Тести проекту

Проект-шаблон вже "з коробки" містить деякі прості примірники тестів. Спираючись на них, можна реалізовувати повноцінні тести нововпровадженого коду.

Більш детально у секції [Побудова проекту](/doc/sections/uk_UA/5-project-build.md) про те як увімкнути підтримку побудови тестів за допомогою CMake.

Проект несе три різновиди тестів, кожен за власним параметром, і всі вони зареєстровані у `ctest`:

| Параметр | Тести |
| --- | --- |
| `ENABLE_UNIT_TESTS` | виконувані файли GoogleTest `UTEST_*`, по одному класу під тестом у кожному, з підміненим усім оточенням |
| `ENABLE_COMPONENT_TESTS` | виконувані файли GoogleTest `CTEST_*`, які проганяють цілий компонент через справжніх співробітників, з яких його побудовано |
| `ENABLE_INTEGRATION_TESTS` | скрипти оболонки `ITEST_*` з [src/tests/integration](/src/tests/integration), які проганяють отриманий виконуваний файл так, як це робить користувач |

Інтеграційні тести нічого не компілюють: кожен випадок є скриптом, який `ctest` запускає зі шляхом до виконуваного файлу, який той проганяє, тож перевіряється саме той файл, який було б поставлено користувачу. Тести [ImagesAnnotatorConverter](/src/tests/integration/ImagesAnnotatorConverter) конвертують справжні набори даних виконуваним файлом конвертера і перевіряють, що до нього не потрапив жоден інструментарій графічного інтерфейсу, - див. [Виконуваний файл ImagesAnnotatorConverter](/doc/sections/uk_UA/5-40-the-ImagesAnnotatorConverter-binary.md).
