## Розширення

### Вибір інструментарію інтерфейсу (GTKmm3 / GTKmm4)

Графічний інтерфейс розміщено у `src/gui` і він містить дві взаємозамінні реалізації та незалежний від інструментарію спільний код:

- `src/gui/gtkmm4` — типовий інтерфейс GTKmm4 (GTK 4);
- `src/gui/gtkmm3` — інтерфейс GTKmm3 (GTK 3);
- `src/gui/gtkmm-common` — код, сумісний на рівні вихідних текстів з обома інструментаріями (наприклад, обрізач зображень на основі `Gdk::Pixbuf`).

У єдиний виконуваний файл програми компілюється рівно один інструментарій. Він обирається під час конфігурації взаємовиключними опціями CMake `USE_GTKMM3` / `USE_GTKMM4`. За умовчанням увімкнено `USE_GTKMM4`; увімкнення однієї опції вимагає вимкнення іншої (CMake повідомляє про фатальну помилку, якщо задано обидві або жодної):

```
# за умовчанням - GTKmm4
cmake -S . -B build

# натомість GTKmm3
cmake -S . -B build -DUSE_GTKMM3=ON -DUSE_GTKMM4=OFF
```

### Реалізування UI

Файл `src/gui/gtkmm4/ui/GtkmmWindow.ui` містить типову (GTKmm4) реалізацію інтерфейсу програми; відповідник GTKmm3 — `src/gui/gtkmm3/ui/GtkmmWindow.ui` — може редагуватись за допомогою програми [Glade](https://en.wikipedia.org/wiki/Glade_Interface_Designer). Інтерфейс GTKmm4 використовує формат побудовника GTK4 разом з моделлю меню `Gio::Menu`, що відображається через `Gtk::PopoverMenuBar`, а його пункти меню є діями `Gio::SimpleAction`, а не віджетами пунктів меню.

### Компіляція ресурсів

Щоб запобігти будь-яким залежностям під час встановлення чи виконання програми головний UI-файл дизайну інтерфейсу `GtkmmWindow.ui` і будь-який інший зареєстрований файл ресурсу вбудовується у цільовий бінарний виконуваний файл проекту. Вбудовування ресурсів виконується за допомогою файлу `ui/template.gresource.xml` активного інструментарію (наприклад `src/gui/gtkmm4/ui/template.gresource.xml`), файли якого і будуть компілюватись у C-код за допомогою команди `glib-compile-resources`. Реєструй нові ресурси у цьому файлі для того щоб зробити їх доступними у цільовому виконуваному бінарному файлі проекту. Приклад отримання і використання ресурсів на стороні С++ коду можна переглянути у реалізації компоненту `gtkmm4`.

### Впровадження нових параметрів командного рядка

Для того щоб впровадити нові параметри командного рядка для головного виконуваного файлу проекту необхідно редагувати реалізацію класу `CommandLineParser`. Котрий у свою чергу містить методи розпізнавання параметрів командного рядка котрі передаються об'єктом класу `ApplicationFactory` після виклику головної функції `main` операційною системою.

Необхідно впровадити додаткові члени класу `ApplicationContext` щоб передавати додаткову інформацію з параметрів командного рядка до нащадків абстрактного класу `IApplication` (і відповідно впливати на їхню поведінку у відповідності до вводу користувача) що буде створений за допомогою обє'кта класу `ApplicationFactory` під час виконання розбору параметрів командного рядка.

Бібліотека GTKmm також підтримує деякі параметри командного рядка які передаються їй програмою за замовчуванням.
