## Безперервна інтеграція за допомогою GitHub Actions

Проект містить готовий до використання конвеєр [GitHub Actions](https://docs.github.com/en/actions) за відносним шляхом [.github/workflows/ci.yml](/.github/workflows/ci.yml). Система GitHub знаходить його автоматично, тому відгалуження (fork) репозиторію перевіряється ним без будь-якого додаткового налаштування.

Цей конвеєр є відповідником конвеєра [misc/Jenkinsfile](/misc/Jenkinsfile) для системи GitHub і виконує ті ж самі перевірки:

- `Code format check (clang-format)` - конфігурує проект з `-DENABLE_CLANGFORMAT=ON`, будує ціль `clang-format` і завершується помилкою, якщо та змінила хоча б один відстежуваний файл;
- `Repository hygiene` - завершується помилкою, якщо відстежуваний файл містить маркери конфліктів git;
- `Debug build and tests` - конфігурує проект з `-DCMAKE_BUILD_TYPE=Debug -DENABLE_UNIT_TESTS=ON -DENABLE_COMPONENT_TESTS=ON -DENABLE_SANITIZERS=ON -DMAX_LOG_LEVEL=5`, будує його і запускає модульні та компонентні тести;
- `Every declared test is executed by this pipeline` - відповідник останньої стадії конвеєра Jenkins;
- `Release build and install` - побудова у режимі `Release` з наступною пробною командою `cmake --install`;
- `cppcheck`, `clang-tidy`, `deb package` і `flatpak package` - чотири необов'язкові завдання.

Завдання `Debug build and tests` є матрицею з чотирьох доступних для вибору графічних бібліотек - `gtkmm3` (за замовчуванням), `gtkmm4`, `wxwidgets` і `qt6` - оскільки кожна з них будує власну піддиректорію `src/gui` з власними цілями тестів, і лише всі чотири разом конфігурують кожен оголошений у проекті тест. Компонентні тести виконуються під X-сервером `xvfb-run`: вони будують справжні вікна графічної бібліотеки і самостійно пропускаються за відсутності дисплея, тому без нього вони мовчки залишалися б успішними замість того, щоб бути виконаними.

Кожне завдання матриці зберігає звіти `ctest` у форматі JUnit як артефакт конвеєра, а завдання пакування зберігають створені файли `*.deb` / `*.flatpak`.

Чотири необов'язкові завдання відповідають параметрам `RUN_CPPCHECK`, `RUN_CLANG_TIDY`, `RUN_DEB_PACKAGER` і `RUN_FLATPAK_PACKAGER` конвеєра Jenkins. Вони пропускаються у звичайних запусках і можуть бути запущені

- з вкладки `Actions` репозиторію, шляхом вибору конвеєра `CI`, натискання `Run workflow` і позначення потрібних перемикачів,
- або автоматично щотижневим запуском за розкладом, який вмикає їх усі.

Залежності встановлюються самими завданнями за допомогою `apt-get`, тому використовуються загальносистемні примірники GoogleTest, nlohmann/json та libcurl замість завантаження їх з мережі Інтернет засобами скриптів проекту (див. розділи вимог цієї документації). Для пришвидшення повторних запусків результати компіляції кешуються за допомогою [ccache](https://ccache.dev/) через CMake-змінні `CMAKE_C_COMPILER_LAUNCHER` / `CMAKE_CXX_COMPILER_LAUNCHER` і дію `actions/cache`.
