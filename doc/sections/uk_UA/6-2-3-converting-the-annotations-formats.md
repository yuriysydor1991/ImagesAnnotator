### Конвертація форматів анотацій

Окрім графічного інтерфейсу виконуваний файл несе в собі власний конвертер,
який читає набір анотацій одного формату та записує його назад у іншому
форматі. Він викликається чотирма флагами командного рядка та не відкриває
жодного вікна: застосунок повідомляє про підготовку та про конвертацію лише
повідомленнями журналу, тому він придатний для скрипта та для конвеєра
побудови.

```
# наприклад, з директорії побудови

./src/ImagesAnnotator \
  --convert-from yolo4 \
  --convert-src ./the-existing-dataset \
  --convert-to coco \
  --convert-dst ./the-wanted-dataset
```

- `--convert-from FORMAT` - формат анотацій, який необхідно прочитати,
- `--convert-src PATH` - шлях, з якого необхідно прочитати анотації,
- `--convert-to FORMAT` - формат анотацій, який необхідно записати,
- `--convert-dst PATH` - шлях, у який необхідно записати анотації.

Ці чотири флаги вживаються разом. Вказання лише частини з них є помилкою, і
замість конвертації друкується довідкове повідомлення; якщо не вказано жодного
з них - як і раніше запускається графічний інтерфейс.

`FORMAT` є одним з наведених нижче імен. Перше з них - це проект анотацій
самого застосунку, файл JSON, який читає та записує бібліотека
[ImagesAnnotator-DataDrivers](https://github.com/yuriysydor1991/ImagesAnnotator-DataDrivers.git),
той самий файл, який відкриває та зберігає меню `Annotations`, а решта дев'ять
- це формати наборів даних бібліотек
[ImagesAnnotator-DataImporters](https://github.com/yuriysydor1991/ImagesAnnotator-DataImporters.git)
та
[ImagesAnnotator-DataExporters](https://github.com/yuriysydor1991/ImagesAnnotator-DataExporters.git),
ті самі, які пропонують підменю імпорту та експорту:

| `FORMAT` | Анотації, які він позначає |
| --- | --- |
| `imagesannotator` | файл JSON проекту анотацій самого застосунку |
| `plain-txt` | текстові файли з одним рядком на прямокутник |
| `yolo4` | тренувальна директорія darknet YOLO v4 |
| `ultralytics-detect` | набір даних виявлення Ultralytics YOLO |
| `ultralytics-obb` | набір даних орієнтованих обмежувальних рамок Ultralytics YOLO |
| `ultralytics-segment` | набір даних сегментації екземплярів Ultralytics YOLO |
| `coco` | описовий файл JSON виявлення об'єктів COCO |
| `pascal-voc` | набір файлів XML Pascal VOC |
| `createml` | описовий файл JSON виявлення об'єктів Create ML |
| `pytorch` | структура директорій `ImageFolder` PyTorch Vision |

Для формату `imagesannotator` шлях є самим файлом JSON проекту, а для будь-якого
іншого - директорією, яка містить набір даних. Директорія призначення, якої ще
не існує, створюється.

Формат `pytorch` придатний лише як джерело. Запис цього формату вирізає кожен
анотований прямокутник із зображення, на якому його було намальовано, а
вирізання виконується засобами обробки зображень того графічного інструментарію,
з яким було зібрано застосунок, а його конвертація ніколи не запускає. Читання
цього формату працює так само, як і будь-якого іншого джерела.

Обидві половини конвертації є тими самими, які виконують пункти меню: джерело
читається у проект анотацій, який редагує застосунок, а потім цей проект
записується у форматі призначення. Тому конвертація проходить через ті самі
читачі та записувачі, які використовує графічний інтерфейс, і поводиться саме
так, як поводилася б відповідна пара пунктів меню, а у шлях, який читається, як
і при імпорті, ніколи нічого не записується.

Статус завершення дорівнює нулю, коли обидві половини завершились успішно, та
відрізняється від нуля у іншому випадку - для невідомого імені формату,
нечитабельного джерела, директорії призначення, яку неможливо створити, або
порожнього результату.
