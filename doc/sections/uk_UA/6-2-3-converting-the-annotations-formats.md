### Конвертація форматів анотацій

Окрім графічного інтерфейсу виконуваний файл несе в собі власний конвертер,
який читає набір анотацій одного формату та записує його назад у іншому
форматі. Він викликається чотирма флагами командного рядка та не відкриває
жодного вікна: застосунок повідомляє про підготовку та про конвертацію лише
повідомленнями журналу, тому він придатний для скрипта та для конвеєра
побудови.

```
# наприклад, з директорії побудови

./src/ImagesAnnotator \
  --convert-from yolo4 \
  --convert-src ./the-existing-dataset \
  --convert-to coco \
  --convert-dst ./the-wanted-dataset
```

Проект також будує другий виконуваний файл, `ImagesAnnotatorConverter`, який
несе саме цю конвертацію і жодного графічного інтерфейсу - ті самі флаги, ті
самі формати, ту саму поведінку, - і який можна побудувати та встановити
окремо, без жодного наявного інструментарію графічного інтерфейсу. Див.
[Виконуваний файл
ImagesAnnotatorConverter](/doc/sections/uk_UA/5-40-the-ImagesAnnotatorConverter-binary.md).

- `--convert-from FORMAT` - формат анотацій, який необхідно прочитати,
- `--convert-src PATH` - шлях, з якого необхідно прочитати анотації,
- `--convert-to FORMAT` - формат анотацій, який необхідно записати,
- `--convert-dst PATH` - шлях, у який необхідно записати анотації.

Ці чотири флаги вживаються разом. Вказання лише частини з них є помилкою, і
замість конвертації друкується довідкове повідомлення; якщо не вказано жодного
з них - як і раніше запускається графічний інтерфейс.

`FORMAT` є одним з наведених нижче імен. Перше з них - це проект анотацій
самого застосунку, файл JSON або imgajz1, який читає та записує бібліотека
[ImagesAnnotator-DataDrivers](https://github.com/yuriysydor1991/ImagesAnnotator-DataDrivers.git),
той самий файл, який відкриває та зберігає меню `Annotations`, а решта тринадцять
- це формати наборів даних бібліотек
[ImagesAnnotator-DataImporters](https://github.com/yuriysydor1991/ImagesAnnotator-DataImporters.git)
та
[ImagesAnnotator-DataExporters](https://github.com/yuriysydor1991/ImagesAnnotator-DataExporters.git),
ті самі, які пропонують підменю імпорту та експорту:

| `FORMAT` | Анотації, які він позначає |
| --- | --- |
| `imagesannotator` | файл проекту анотацій самого застосунку: стиснений gzip файл imgajz1 або файл JSON |
| `plain-txt` | текстові файли з одним рядком на прямокутник |
| `yolo4` | тренувальна директорія darknet YOLO v4 |
| `ultralytics-detect` | набір даних виявлення Ultralytics YOLO |
| `ultralytics-obb` | набір даних орієнтованих обмежувальних рамок Ultralytics YOLO |
| `ultralytics-segment` | набір даних сегментації екземплярів Ultralytics YOLO |
| `coco` | описовий файл JSON виявлення об'єктів COCO |
| `pascal-voc` | набір файлів XML Pascal VOC |
| `createml` | описовий файл JSON виявлення об'єктів Create ML |
| `pytorch` | структура директорій `ImageFolder` PyTorch Vision |
| `dxxwjz2` | тренувальна директорія darknetxx: директорія YOLO v4 з мережею dxxwjz2 для тренування |
| `dxxwjz2p` | тренувальний проект darknetxx dxxwjz2p |
| `dxxwjz3` | тренувальна директорія darknetxx: директорія YOLO v4 з мережею dxxwjz3 для тренування |
| `dxxwjz3p` | тренувальний проект darknetxx dxxwjz3p |

Для формату `imagesannotator` шлях є самим файлом проекту, а для будь-якого
іншого - директорією, яка містить набір даних; шлях джерела проектів `dxxwjz2p`
та `dxxwjz3p` може називати і сам файл проекту. Директорія призначення, якої ще
не існує, створюється.

Формат файлу проекту для шляху `imagesannotator` визначає розширення імені
файлу, з обох боків конвертації: шлях з розширенням `.imgajz1` - це файл
проекту imgajz1, рідний для застосунку, - стиснений gzip файл проекту JSON, - а
будь-який інший шлях - звичайний файл проекту JSON. Тож рідний проект
конвертується і між двома своїми файлами:

```
# проект JSON у проект imgajz1, приблизно в 16 разів менший

./src/ImagesAnnotator \
  --convert-from imagesannotator \
  --convert-src ./cars.json \
  --convert-to imagesannotator \
  --convert-dst ./cars.imgajz1
```

Запис формату `pytorch` вирізає кожен анотований прямокутник із зображення, на
якому його було намальовано, тож ця єдина з тринадцяти розкладок читає самі пікселі
зображень, а не лише їхні анотації. Обрізачів, які реалізують графічні
інструментарії цього застосунку, конвертація не має, бо не запускає жодного
інтерфейсу, тому вирізання виконує обрізач зображень на основі OpenCV, який
бібліотека
[ImagesAnnotator-DataExporters](/doc/sections/uk_UA/5-37-enabling-the-ImagesAnnotator-DataExporters-library.md)
постачає сама. Саме його збирає її параметр `ENABLE_OPENCV`, а він типово
увімкнений, тож звичайна встановлена бібліотека конвертує у цю розкладку так
само, як і в будь-яку іншу. Встановлена з `-DENABLE_OPENCV=OFF` або на машині
без пакетів розробки OpenCV бібліотека обрізача не несе - і тоді єдине це
призначення завершується помилкою, про яку бібліотека повідомляє, тоді як
читання цієї розкладки працює в обох випадках.

Обидві половини конвертації є тими самими, які виконують пункти меню: джерело
читається у проект анотацій, який редагує застосунок, а потім цей проект
записується у форматі призначення. Тому конвертація проходить через ті самі
читачі та записувачі, які використовує графічний інтерфейс, і поводиться саме
так, як поводилася б відповідна пара пунктів меню, а у шлях, який читається, як
і при імпорті, ніколи нічого не записується.

Статус завершення дорівнює нулю, коли обидві половини завершились успішно, та
відрізняється від нуля у іншому випадку - для невідомого імені формату,
нечитабельного джерела, директорії призначення, яку неможливо створити, або
порожнього результату.
