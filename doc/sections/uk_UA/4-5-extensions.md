## Розширення

### Вибір інструментарію інтерфейсу (GTKmm3 / GTKmm4)

Графічний інтерфейс розміщено у `src/gui` і він містить дві взаємозамінні реалізації та незалежний від інструментарію спільний код:

- `src/gui/gtkmm4` — типовий інтерфейс GTKmm4 (GTK 4);
- `src/gui/gtkmm3` — інтерфейс GTKmm3 (GTK 3);
- `src/gui/gtkmm-common` — код, сумісний на рівні вихідних текстів з обома інструментаріями (наприклад, обрізач зображень на основі `Gdk::Pixbuf`), а також єдиний примірник незалежних від інструментарію ресурсів GResource у `src/gui/gtkmm-common/ui/resources`.

У єдиний виконуваний файл програми компілюється рівно один інструментарій. Він обирається під час конфігурації взаємовиключними опціями CMake `USE_GTKMM3` / `USE_GTKMM4`. Задавати потрібно лише ту опцію, яка цікавить — та, що залишилась незаданою, виводиться з неї, тому пара ніколи не стане суперечливою:

```
# нічого не задано - GTKmm4, за умовчанням
cmake -S . -B build

# натомість GTKmm3: USE_GTKMM4 вимикається автоматично
cmake -S . -B build -DUSE_GTKMM3=ON

# рівнозначний і так само коректний виклик
cmake -S . -B build -DUSE_GTKMM4=OFF
```

Задання обох опцій одночасно теж приймається, якщо рівно одна з них `ON`; CMake повідомляє про фатальну помилку, коли обидві `ON` або обидві `OFF`. Повторний запуск `cmake` у наявному каталозі збірки зберігає той інструментарій, з яким його було сконфігуровано, а повторне задання однієї опції перемикає його — наприклад, `cmake -S . -B build -DUSE_GTKMM4=ON` переводить дерево GTKmm3 на GTKmm4.

Усе, що випливає з цього вибору, оголошується відповідним активатором — `cmake/enablers/template-project-Gtkmm3-enabler.cmake` або `cmake/enablers/template-project-Gtkmm4-enabler.cmake`: перевірка `pkg-config`, що публікує змінні `GTKMM_*` для всього піддерева `src`, підкаталог `src/gui` для компіляції, препроцесорне визначення `USE_GTKMM3` / `USE_GTKMM4`, яке підхоплює незалежний від інструментарію фасад `src/gui/GuiIniter.h`, та назва пакунка середовища виконання GTKmm для пакувальника DEB. Сама ж пара опцій розв'язується один раз у `cmake/template-project-misc-variables-declare.cmake` — єдиному місці проекту, де є розгалуження за нею.

### Реалізування UI

Файл `src/gui/gtkmm4/ui/GtkmmWindow.ui` містить типову (GTKmm4) реалізацію інтерфейсу програми; відповідник GTKmm3 — `src/gui/gtkmm3/ui/GtkmmWindow.ui` — може редагуватись за допомогою програми [Glade](https://en.wikipedia.org/wiki/Glade_Interface_Designer). Інтерфейс GTKmm4 використовує формат побудовника GTK4 разом з моделлю меню `Gio::Menu`, що відображається через `Gtk::PopoverMenuBar`, а його пункти меню є діями `Gio::SimpleAction`, а не віджетами пунктів меню.

### Компіляція ресурсів

Щоб запобігти будь-яким залежностям під час встановлення чи виконання програми головний UI-файл дизайну інтерфейсу `GtkmmWindow.ui` і будь-який інший зареєстрований файл ресурсу вбудовується у цільовий бінарний виконуваний файл проекту. Вбудовування ресурсів виконується за допомогою файлу `ui/template.gresource.xml` активного інструментарію (наприклад `src/gui/gtkmm4/ui/template.gresource.xml`), файли якого і будуть компілюватись у C-код за допомогою команди `glib-compile-resources`. Реєструй нові ресурси у цьому файлі для того щоб зробити їх доступними у цільовому виконуваному бінарному файлі проекту. Приклад отримання і використання ресурсів на стороні С++ коду можна переглянути у реалізації компоненту `gtkmm4`.

Записи `<file>` обох файлів `template.gresource.xml` розшукуються у двох каталогах, які файл `ui/CMakeLists.txt` відповідного інструментарію передає команді `glib-compile-resources` як `--sourcedir`: спочатку власний каталог `ui` інструментарію, а потім спільний `src/gui/gtkmm-common/ui`. Тому специфічні для інструментарію ресурси, такі як `GtkmmWindow.ui`, залишаються поруч зі своїм інструментарієм, а ресурси, які побайтово однакові для GTKmm3 і GTKmm4 — CSS та зображення — зберігаються лише один раз у `src/gui/gtkmm-common/ui/resources` і вбудовуються обома. Новий спільний ресурс додавай до цього каталогу і реєструй в обох файлах `template.gresource.xml` за тим самим відносним шляхом; специфічний для інструментарію — до `src/gui/gtkmm3/ui` або `src/gui/gtkmm4/ui`. Префікс ресурсів залишається окремим для кожного інструментарію (`.../gtkmm3/...` проти `.../gtkmm4/...`), тому спільне використання не впливає на шляхи часу виконання, які використовує `WindowDataContext`.

### Впровадження нових параметрів командного рядка

Для того щоб впровадити нові параметри командного рядка для головного виконуваного файлу проекту необхідно редагувати реалізацію класу `CommandLineParser`. Котрий у свою чергу містить методи розпізнавання параметрів командного рядка котрі передаються об'єктом класу `ApplicationFactory` після виклику головної функції `main` операційною системою.

Необхідно впровадити додаткові члени класу `ApplicationContext` щоб передавати додаткову інформацію з параметрів командного рядка до нащадків абстрактного класу `IApplication` (і відповідно впливати на їхню поведінку у відповідності до вводу користувача) що буде створений за допомогою обє'кта класу `ApplicationFactory` під час виконання розбору параметрів командного рядка.

Бібліотека GTKmm також підтримує деякі параметри командного рядка які передаються їй програмою за замовчуванням.
